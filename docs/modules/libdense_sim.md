# libdense_sim

High-density dynamic spatial subscription and fanout planning kernel.

## Current invariants

- One `ds_world` has one writer.
- Mutations happen only inside an open tick.
- Tick numbers increase monotonically.
- Public entity IDs are arbitrary `uint64_t` values and never serve as array indexes.
- Public entity IDs map to compact `uint32_t` dense slots.
- Entity hot state is stored in separate arrays.
- Removing an entity keeps entity storage dense through swap-remove.
- Dense entity relocation repairs ID, spatial, dirty, subscription-change, anchor-head, and visibility-head references.
- Public observer IDs are stable `uint64_t` handles generated by the kernel.
- Observer internals use stable pooled slots because persistent relation nodes refer to observer slots.
- `chunk_size` is an exact multiple of `cell_size`.
- Negative coordinates use mathematical floor division rather than C truncation toward zero.
- Cell and chunk buckets are allocated only for occupied coordinates.
- Cell and chunk membership use intrusive slot links for O(1) unlink/link repair.
- A movement transition computes old/new cell and chunk coordinates once.
- Cell repair and chunk repair consume the same centralized transition.
- Crossing records are internal shared facts, not public replication output.
- Dirty channels are application-defined `uint64_t` masks.
- An entity appears at most once in the dirty slot vector per tick.
- Repeated dirty marks OR into the entity mask without appending another slot.
- Dirty reset touches only entities that were dirty in the prior finalized tick.
- Movement does not automatically choose a dirty channel for the application.
- Observer chunk subscriptions are persistent and maintained by rectangle boundary differences.
- Observer visibility membership is maintained incrementally from observer coverage changes, entity chunk transitions, spawns, and removals.
- ENTER and LEAVE work represents finalized membership, not transient mutation order within a tick.
- Internal linear-probing maps use cluster reinsertion on erase and do not accumulate tombstones.
- Internal slots are not part of the public ABI.
- No application payload is owned by the kernel.
- Finalized fanout views are borrowed and remain valid until the next successful `ds_world_begin_tick`.
- A `ds_chunk_delta` is an exact recipient group; the same spatial chunk may appear more than once when subscriber spans differ.
- UPDATE deltas carry coalesced channel masks; ENTER and LEAVE carry a zero mask and let the consumer choose snapshot/removal encoding.
- Sampled movement remains the default entity motion path.
- Kinetic motion is selective and requires an explicit stable linear motion plan.
- Kinetic certificates represent next cell crossings, not per-tick position updates.
- Kinetic repair runs before subscription finalization and fanout in `ds_world_end_tick`.
- Active-plan replacement uses lazy token invalidation; stale scheduled events are not searched and removed eagerly.
- Kinetic spatial repair consumes the same centralized entity-transition path as sampled movement.
- Kinetic movement does not automatically choose an application dirty channel.
- Entities with anchored observers cannot use kinetic motion in v0.1 because observer-coverage certificate boundaries are distinct from entity cell boundaries.

## Current movement and observer path

```text
ds_entity_move
        |
        v
public ID -> dense entity slot
        |
        v
exact-position no-op?
        |
        v
reserve anchored-observer dirty capacity
        |
        v
compute destination cell once
        |
        +-- same cell -> update x/y
        |                  |
        |                  v
        |            update anchor positions
        |
        v
prepare cell/chunk transition work
        |
        v
centralized transition commit
        |
        +-- repair cell membership
        +-- repair chunk membership when changed
        +-- coalesce first-old/final-new chunk transition
        +-- update anchor positions
        +-- append one internal crossing fact
```

Anchored observer positions consume the known entity position mutation directly. This is necessary because `position +/- radius` can cross a chunk edge during a same-cell entity move.

Raw crossings remain internal. The intended public finalized work surface is the fanout plan described by `design_pattern.md`.

## Current selective motion path

```text
sampled motion
    ds_entity_move
        |
        v
    centralized spatial transition

stable linear plan
    ds_entity_set_motion_plan
        |
        v
    solve next cell-certificate failure tick
        |
        v
    pooled event in due-tick bucket
        |
        v
    end_tick batch drain
        |
        v
    centralized spatial transition
        |
        v
    schedule next failure or expiry
```

The kinetic scheduler uses a sparse tick-to-bucket map and a min-heap over
**unique due ticks**. Events due on the same tick remain pooled in one intrusive
bucket list so simultaneous certificate failure is the normal repair path.

Plan replacement assigns a new token and leaves the old event scheduled. A
later token mismatch drains stale without searching the event pool. Explicit
clear and successful sampled movement demote an active plan. The public entity
getter derives the current integer position from an active trajectory even
between certificate failures; spatial membership itself is repaired only when a
cell certificate fails.

The exact sampled-vs-kinetic equivalence, churn, mixed-motion, and regression
results are documented in
[`benchmarks/MILESTONE_8_REPORT.md`](benchmarks/MILESTONE_8_REPORT.md).

## Current dirty path

```text
application mutation
        |
        v
ds_entity_mark_dirty(id, channel_mask)
        |
        v
public ID -> dense slot
        |
        v
first dirty mark this tick?
        |
        +-- yes -> append slot once
        |
        v
dirty_mask[slot] |= channel_mask
```

The internal hot primitive accepts a dense slot directly. First-party systems such as future DenseDB storage can preserve a change at the mutation site without redoing a public-ID lookup when they already own the resolved slot.

## Current observer subscription path

```text
observer desired position/radius
        |
        v
coarse chunk rectangle
        |
        v
same as applied rectangle?
        |
        +-- yes -> no subscription work
        |
        v
rectangle boundary difference
        |
        +-- entering chunk strips
        +-- leaving chunk strips
        |
        v
persistent observer <-> chunk relation
        |
        v
reconcile affected entity membership
        |
        +-- ENTER
        +-- LEAVE
```

The subscription graph is stored in both directions. Fanout planning consumes the chunk-to-observer direction once per dirty chunk/type-mask run, rather than walking the observer population or rebuilding per-entity visibility sets.

## Current fanout path

```text
finalized membership changes
        |
        +-- aggregate ENTER / LEAVE by entity and exact recipients
        |
        v
dirty entity slots
        |
        v
sort by chunk + entity type mask
        |
        v
scan that chunk's persistent subscriber list once per type-mask run
        |
        v
exact subscriber span
        |
        v
merge bundles with identical chunk + subscriber span
        |
        v
borrowed ds_fanout_view
```

Every delta in a `ds_chunk_delta` applies to every observer in that group's subscriber span. Equivalent recipient sets share one delta body plan. Heterogeneous observer type masks may produce multiple groups for the same spatial chunk.

Same-tick ENTER recipients are removed from an UPDATE span for that entity because the ENTER snapshot is expected to read final application state. Existing recipients still receive the UPDATE.

The dirty vector, crossing vector, subscription graph, membership change buffers, grouping hash tables, and scratch arenas remain internal.

## Milestone 6 benchmark and architecture-repair status

The benchmark/falsification round and Milestone 6A/6B repair are complete.

Run the default scenario ladder with:

```bash
make benchmark-m6
```

Run matched aggressive/native flags across the preserved references and the
kernel with:

```bash
make benchmark-m6-native
```

The suite now covers:

```text
dense_all_to_all
    identical 24x24 random walk used by the naive/optimized references
    known-slot core path and public-ID ABI path

town_square
    fixed hot set with total sparse world population growth

chunk_crossing
    same-cell fast path and forced chunk-boundary thrash

boundary_thrash
    persistent observer coverage edge churn with ENTER/LEAVE fanout

fanout_fragmentation
    1 through 64 exact recipient sets at near-constant delivery volume
```

The benchmark paths report p50/p95/p99/worst timing and work counters for:

```text
dirty entities
dirty channels
cell crossings
chunk crossings
observer transitions
subscription ENTERs
subscription LEAVEs
fanout groups
fanout deltas
subscriber references
implied deliveries
```

Milestone 6 proves that fixed hot-set fanout work is independent of total world
population and that UPDATE delivery cross-products remain implicit in the
borrowed plan.

Milestone 6A/6B then repaired the two architecture deviations exposed by that
benchmark round:

```text
entity chunk crossing
    compare cached exact old/new chunk+type recipient spans
    equal spans perform zero membership work
    unequal spans reconcile only the linear symmetric difference

ENTER/LEAVE fanout
    accumulate finalized membership changes directly by chunk/op/entity
    consume grouped work directly without flat pair expansion or global sort
```

The same-session native control comparison at 1,000 dense players moved from:

```text
2.549 ms mean tick
2.326 ms subscription phase
90.26 MiB retained tick/fanout memory
```

to:

```text
0.258 ms mean tick
0.151 ms subscription phase
24.37 MiB retained tick/fanout memory
```

At 1,000 observers in boundary thrash, fanout moved from 10.953 ms to 0.705 ms
while the workload still produced 60,000 ENTER and 60,000 LEAVE pairs per tick
and the same 12-group/120-delta public plan.

The original falsification record is retained in
[`benchmarks/MILESTONE_6_REPORT.md`](benchmarks/MILESTONE_6_REPORT.md). The
repair analysis and before/after control data are documented in
[`benchmarks/MILESTONE_6_REPAIR_REPORT.md`](benchmarks/MILESTONE_6_REPAIR_REPORT.md).

Milestone 8 intentionally expands the public C ABI to 28 exported functions by adding motion-plan assignment, explicit motion-plan clear/demotion, motion-mode lookup, and cumulative motion metrics. The next intended implementation milestone is the C++ and Rust wrapper layer.
